# F2 Decisiones abiertas — research 2026-10-31 (no commit)

## D1. Login manager — Ruling: SDDM 0.21.0 para F2; PLM 6.8.2 en spike F8; greetd descartado
- `plasma-login-manager` 6.8.2 (extra, parte de plasma-meta 6.8): fork SDDM + greeter fijo Breeze + KCM "Login Screen" + `WallpaperPluginId`; conf `/etc/plasmalogin.conf(.d/)`, servicio `plasmalogin`, autologin `[Autologin] User/Session=plasma.desktop`; kwallet vía wiki KDE Wallet igual que SDDM; exige systemd; NO admite temas QML arbitrarios; layout teclado aún X11 (`localectl`); Fedora 44 default (FESCo #3523) y CachyOS ISO 2026-01 lo adoptan. Fuentes: ArchWiki Plasma_Login_Manager (ed. 2026-09-04), fedoraproject.org/wiki/Changes/PlasmaLoginManager, 9to5linux CachyOS 2026-01.
- SDDM 0.21.0-7 (extra, GPL-2.0): estable, temas QML, `sddm-kcm` 6.8.2 con "Apply Plasma Settings", greeter X11 por defecto + Wayland experimental (`DisplayServer=wayland`, `CompositorCommand=kwin_wayland…`, requiere `layer-shell-qt`).
- greetd (+tuigreet/regreet/qtgreet): mínimo, Wayland-nativo, `config.toml` `[initial_session]` para autologin; pero pierde KCM y kwallet no se desbloquea en autologin sin `pam_fde_boot_pw` (AUR) — NixOS Discourse #29195, ArchWiki greetd.
- Ruling D1: NimbusOS usa `sddm` en F2/F9 (Calamares `displaymanager.conf` upstream NO lista `plasma-login-manager` — solo sddm/lightdm/gdm/…/greetd); re-evaluar PLM cuando su módulo Calamares exista.

## D2. Calamares — orden unificado F2/F9
- `settings.conf` canónico: show `[welcome, locale, keyboard, partition, users(, netinstall/packagechooser), summary]` → exec `[partition, mount, unpackfs, machineid, fstab, locale, keyboard, localecfg, packages(+netinstall), users, displaymanager, networkcfg, hwclock, services-systemd, bootloader/grub, umount]` → show `[finished]`. Fuente: `calamares/calamares:settings.conf` + `calamares.io/docs` (Users Guide, Deploy-Configuration).
- Necesarios: welcome, locale, keyboard, partition (+LUKS `enableLuks`), users (`doAutologin`), displaymanager (`displaymanagers:[sddm]`, `basicSetup:true`), packages, fstab, bootloader (grub/systemd-boot), mount/unpackfs/machineid/networkcfg, summary/finished. Opcionales: tracking, notesqml, plasmalnf, packagechooser-licenseq. netinstall = instancia `module:netinstall` (p. ej. `netinstall-nimbus.conf`) en show + job `packages` en exec (patrón biglinux-livecd `install_service.py`).
- Ruling D2: F2 congela ese orden; pregunta del brief (`grub` vs `bootloader`, `fstab?`, `removeuser`, `displaymanager` antes de `packages`) se resuelve: usar `bootloader` (grub es solo conf), `fstab` sí, `removeuser` solo en OEM (`dont-chroot`), `displaymanager` después de `users/packages` en exec.

## D3. WhiteSur / R-APPLE — auditar antes de usar; ATTRIBUTION obligatoria
- Licencias upstream (vinceliuice): `WhiteSur-kde` GPL-3.0, `WhiteSur-gtk-theme` MIT, `WhiteSur-icon-theme` GPL-3.0 (versión nixpkgs 2026-09-10, libre). Son arte propio "MacOS-like", no redistribuyen binarios Apple/SF/wallpapers/sonidos; PERO `install.sh` de iconos trae flag `-p/--kde-plasma` ("Replace Apple logo with KDE Plasma logo") → el default SÍ incluye logo Apple: usar `-p` o parchear. Wallpapers del repo son propios (`WhiteSur Wallpapers`); prohibido añadir `.jpg/.png` de macOS.
- Verificación obligatoria en VM/host: `grep -rli "apple\|sf pro\|garageband\|aabegin" WhiteSur*/ ; find WhiteSur* -iname "*apple*" -o -iname "*.sfnt" -o -iname "*.otf" | head; grep -rli "cupertino\|macos.*logo" src/ | head; fc-list | grep -i "sf "` + registrar `sha256sum` de assets propios en `assets/`.
- Ruling D3 (R-APPLE): solo WhiteSur-kde/gtk/icons con `-p`, sin wallpapers/sonidos externos; sustituir logo N + Inter + Sequoia NPS propios; ATTRIBUTION en README + `NOTICE` (autor vinceliuice, licencia, URL, commit pin).

## D4. KRunner fullscreen — no hay API oficial; recomendación F6-T01 = FreeFloating + tema
- KRunner (Frameworks 6.31.0) se muestra vía `plasma-workspace/krunner/qml/RunCommand.qml` del look-and-feel (`/usr/share/plasma/look-and-feel/*/contents/runcommand/`); única opción soportada: `kwriteconfig6 --file krunnerrc --group General --key FreeFloating true` (centrado, efectivo tras login; ArchWiki KRunner + System Settings → "Position on screen"). No existe modo fullscreen/overlay en `krunnerrc` ni D-Bus.
- Alternativa overlay propio layer-shell-qt (ventana fullscreen transparente que embebe RunnerModel de milou/Kicker): coste medio-alto, riesgo de rotura en cada Plasma 6.x + pérdida de atajos globales; solo si el spike F6 demuestra `FreeFloating` insuficiente para el clon Spotlight.
- Ruling D4: F6-T01 = `FreeFloating=true` + skin QML del look-and-feel Nimbus (parche mínimo documentado); overlay fullscreen queda como T-opcional con Ruling propia.
